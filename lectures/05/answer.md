- 検索だけを実行して見つかったページと、その本文で確認できたこと：

  `uv run python -m app.retrieval "LoRA QLoRA 違い"`を実行したところ、第2回のPDF p.52、51、60、47、61の5ページが表示された。

  特にp.52には、LoRAでは元の重みを固定し、行列A・Bで表される小さな差分だけを学習すること、QLoRAではさらに元の重みを4bitに圧縮することが明記されていた。p.51にも同様の説明があり、今回の質問に答えるための根拠として十分だった。一方、p.60やp.61はQLoRAの演習に関する内容であり、質問に直接答えるためには必須ではなかった。

- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：

  全文投入ではツール呼び出しはなく、資料全体を入力して1回のモデル応答で回答した。

  ベクトル検索では`search_materials({'query': 'LoRA QLoRA 固定 学習'})`が1回呼び出された。

  Treeでは`browse_tree`が4回呼び出された。最初に講義一覧を取得し、第2回「基盤モデルの仕組み」→「選んだモデルを、いつ・どう直すか」→PDF p.52という順番で目次をたどり、最終的に`lec02-main-p052`の本文717文字を取得した。

  Graphでは`search_graph({'query': 'LoRA QLoRA 固定 学習'})`が1回呼び出された。ベクトル検索で関連ページを見つけ、周辺の関連情報も取得する方式だった。

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：

  今回の質問では、どの方式も必要な根拠となるページを特定できていた。しかし、全文投入ではp.51、52を正しく示していたにもかかわらず、具体的な答えを出さずにヒントだけを提示した。これは情報が不足したのではなく、取得した情報を回答に十分活用できなかった例だと考えられる。

  また、ベクトル検索では回答に直接必要のないp.60やp.61も取得されており、検索結果に不要な情報が混ざることも確認できた。

- 今回の用途に採用したい方式と、その理由・比較条件の限界：

  今回のように特定の用語や仕組みを質問する用途では、ベクトル検索を採用したい。正確な回答が得られ、入力トークン数3,027、推定費用0.001236ドルと、今回の4方式の中で最も少なかったためである。

  Treeは目次を順番にたどるため時間とトークン数が増え、Graphも関連ページを広く取得する分、入力が多くなった。ただし、全文投入だけ対象資料の範囲が異なり、各方式1回ずつの実験なので、今回の結果だけで方式全体の優劣を判断することはできない。

- 気づき・疑問：

  全文投入は情報量が最も多いにもかかわらず、直接的な回答が得られなかったことが印象的だった。情報を大量に与えるよりも、必要な情報を適切に選んで渡す方が効果的な場合があると感じた。また、今回のような単純な質問ではベクトル検索が効率的だったが、複数の章にまたがる質問ではGraphやTreeの方が有利になるのか気になった。
